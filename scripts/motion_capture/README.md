# 使用现有App补采移动姿态，不安装新版

用途：核实Pocket机身转动时，50字节姿态包各字段的实际含义。当前App诊断不包含这些原始四元数，无法靠再次校准补出。本工具只被动读取现有App的网络姿态回报，不向相机发指令，不修改固定模式。

本机已有`rvictl`和`tcpdump`，无需完整Xcode、额外软件或付费服务。解析器12项测试通过；当前没有USB连接的iPhone，RVI真机采集尚未运行，不能将解析器测试写成实际采集成功。

## 操作

1. USB连接并解锁iPhone。继续用现有HeadLink 1.2.0正常连接Pocket，**暂停头部跟随**，机身选Follow。无需重校准或改iPhone权限。
2. 在Mac终端运行：

   ```sh
   python3 /Users/wch/Documents/Codex/2026-10-16/new-chat/outputs/HeadLink-motion-capture/attitude_capture.py
   ```

仓库内也可运行`python3 scripts/motion_capture/attitude_capture.py`。

3. 按Enter后，脚本请求Mac本机管理员授权，用于读取USB网络镜像接口。密码只在本机终端输入，不发到聊天。采集总计70秒，跟随终端提示依次：静止10秒、机身左右转15秒、机身前后倾15秒、机身侧倾15秒、机身固定仅动摇杆15秒。各动作缓慢，约20°～30°，中间保持约2秒，不推到止挡。
4. 输出本目录的`HeadLink-moving-attitude.json`。只有`captureSucceeded=true`且`sampleCount>0`才是有效采集；可提供该JSON。错误时保留错误文本，不需要重校准、重装App或反复重新设置权限。

自动USB识别失败时，可在Finder设备页点击设备编号切换到UDID，使用`--udid`参数在本机传入。设备编号不写入JSON，也无需发到聊天。

## 数据边界

- 内核过滤相机UDP9004控制包，排除视频；仅CRC正确的0x04/0x05、50字节姿态负载才落盘。
- 不保存pcap、视频、Wi-Fi信息、网络地址或设备UDID；输出含姿态原始50字节及已知角度、四元数候选、尚未定性的数值字段。
- 抓包时间明确标为**网络收包时刻**，不冒充传感器测量时刻；动作阶段是提示标签，不冒充外部角度真值。
- 四元数存在且单位化不等于已经验证其航向参考、倾斜握持符号或完整机身姿态。分析后才能决定控制绑定，不把目标值写成反馈。
- 脚本达到70秒或6000条就停止，清理自己建立的RVI接口。Ctrl+C也会进入停止清理。与原App录像/图传状态独立。
