# 挂脖移动：故障定位与交付边界

2026-10-17。安装：Pocket 4挂脖随胸口移动、转动、倾斜；iPhone分离。用户已实测通过固定机身1∶1。固定版1.2.0（8）保存于标签`baseline-fixed-1.2.0-build-8`，main未替换。独立开发分支`research/moving-body-observability`中的1.2.1只用于稳定性修复与补证，**不是接通挂脖补偿的成品**。

## 目前能证明什么

没有收到本次“移动即断连”的运行诊断。现有Downloads文件是旧schema2，不能据此确定本次触发源。下面是源码确认的路径及其修复，不能写成已经复现用户故障。

| 触发 | 1.2.0（8）行为/位置 | 本次修改 |
| --- | --- | --- |
| 图传停滞，两次重新注册/请求流无效 | `Sources/HeadLinkCore/VideoRecoveryPolicy.swift`第三次动作重建共享UDP；`App/PocketCamera+Video.swift`通知App清校准，重建10秒超时会关闭全会话 | 真实控制回报3秒内仍更新时，禁止因视频失败自动重建共享UDP；保留控制与校准，图传独立提示并允许手动有界重试。控制也失效时仍只给一次共享重建 |
| SDK flowHealthy为false持续1秒 | `App/PocketCamera.swift:checkHealth()`直接disconnect，未独立核对收到的控制/视频证据 | 同一个1秒阈值，但只有本地传输不可用且控制、视频收包均无新鲜证据时才清理；收包仍持续时保留会话，发送不可用仍会停止跟随，绝不冒充命令成功 |

| 目标超限、目标队列拒绝、回报偏离 | `TrackingController.tick()`限幅不改倍率；`AppModel.step()`拒绝/偏离只停止目标与跟随；没有调用disconnect | 保留行为，补充限位到达/恢复、模式不兼容、拒绝原因事件，记录同一会话与校准ID |
| 重连前scan/replace_connection | `disconnect()`每次覆盖lastDisconnect；实际故障原因可能被后续“替换连接”覆盖 | 保留最后一次真正关闭已连接会话的原因，空会话清理不覆盖；清理前快照保留命令与姿态 |

`isFlowHealthy`是本地SDK写入健康与NWConnection.ready的合取，不等于相机已关机，也不等于手机已离开SSID。底层写入失败、路径标志、socket等待等有不同来源。新诊断保留这些来源可获取的事实；没有RSSI、SSID、相机按键/休眠原因回报时明确不可用。

更底层的`DjiAppleDatalink.tickNativeTarget()`会核对姿态接收时间≤300ms、`GimbalMoveEngine.canSendNativeTarget`规定的现值/目标范围及yaw间距<180°；不满足时取消目标流并发送stop，**不关闭UDP**。之后`noteNativeTarget()`可能只返回false，SDK没有公开细分取消原因；不能把该Bool编造成“相机断开”的证据。倾斜机身是否触发此分支须看同刻真实反馈，不能凭现象认定。`nativeWrites`是底层调用socket send的次数，既不是角度到位证明，也不是相机ACK。

## 最短A/B操作：现有1.2.0（8）即可先做，无需重装

共同条件：在App“设置→显示与反馈”开启“拍摄页保持常亮”；保持App前台，不切系统设置/锁屏。Pocket使用同一Follow模式、同一支架和画面配置；不操作机身按键或屏幕。每组先静止10秒，再慢慢左右转胸口约20°、前后小幅倾斜，最后静止10秒。移动期间留意相机自身屏幕是否退出连接。

1. **A：关闭跟随。** 连接并有预览，点击“暂停跟随”，不必校准。完成上述动作。若出现异常，立刻在App按录像一次，记录相机是否真的开始/停止；若按钮不可用也记录。不要先重新扫描或连接。进入“设置→本地诊断→生成脱敏诊断文件→分享JSON”，保存为A。
2. **B：开启跟随。** 相机与头部先静止，正常校准一次，点击开始，再重复完全相同的动作。B只是复现原固定模式在机身移动时的故障，不是挂脖补偿验收。异常时同样检查一次录像、先导出JSON保存为B，避免反复校准覆盖证据。
3. 导出后再到iPhone“设置→Wi-Fi”查看相机网络是否仍有勾选；记下A/B各自“仍连接/已离开”。这一步会让App进入后台，所以必须在导出后做，不能把它产生的app_background当作原故障。

请提供A、B两份JSON，并各附两项最短观察：录像是否响应；异常发生时相机屏幕是否退出连接。Wi-Fi勾选是事后观察，不冒充故障瞬间的测量。若A、B都不复现，各自持续5分钟再导出，注明未复现。无须重新授权或重复小角度实验。

## 新诊断实现（schema5，开发分支）

- 每200ms一个跨层样本，最多1500条，通常覆盖约5分钟；事件强制增加样本，容量仍有界。前台断连后再记录30秒；应用已后台时不声称还能采样。
- 网络：默认NWPath状态、是否使用Wi-Fi、可用Wi-Fi接口、相机子网地址存在与观测时刻。SSID始终明确不可用；默认路由可能走蜂窝，不能单凭此断言相机Wi-Fi断开。不保存地址/密码。
- 会话：connected、flow健康、endpoint存在/closed/rebuilding、epoch、最后控制回报、最后视频收包、分层分类、关闭前原因；scene事件。
- 输入与输出：耳机接收/传感器时间及四元数、校准ID与具体失效/拒绝原因、原始头部目标、实际提交目标、native pitch、真实镜头反馈/回报时间、模式/参数时间、限位事件、目标提交/真实UDP写入数、SDK最近tracked命令写入结果、录像实报确认/4秒超时。
- 视频：收包、完整AU、解码输出（若原生路径能测）、显示路径回调、解码提交接受时间、恢复动作与原因；AVSampleBuffer压缩路径不能测物理显示时刻，继续明确标注，不把旧帧当实时。
- 相机：仅保留收到的50字节0x04/0x05原始姿态payload及合法镜头四元数，带本机收包时刻。不是完整网络抓包，不含视频、Wi-Fi密码、UDID。无独立机身姿态、相机传感器时间时明确标不可用。
- 设置内A/B标记仅用于诊断分组；A明确暂停跟随，B只标记、仍需用户主动开始，不会自动运动。

## 挂脖补偿真正的阻塞

固定映射用校准角加头部方向差。胸口改变机身朝向时，该映射不能保持空间方向；停在固定模式不代表补偿。包内镜头四元数有上游证据，但完整的机身姿态、关节roll/旋转顺序、倾斜机身下native pitch关系与采样时间还未核实。iPhone分离，不能替代机身IMU。详见`MOVING_BODY_FEASIBILITY.md`的坐标推导与不可观测反例；上游明确列出滚转握持等未验证项：[gimbal-controls](https://raw.githubusercontent.com/erik-sutton95/OpenPocketCine/main/docs/gimbal-controls.md)。

后续需要该机型真实姿态包的受控运动数据来辨识未知字段与复合运动。既有`scripts/motion_capture`可不换App被动采样；它不提供已知的物理角度真值，也不保证一定能从未知字段找到完整机身姿态。若遥测确实不能提供必要量，替代方案是刚性安装的独立姿态传感器或可核实的厂家接口，不能伪造软件输入。不会再询问已经明确的安装方式。

另一条可研究的路线是镜头世界姿态闭环，但仍须核实实际运动轴/雅可比、倾斜握持下的native角关系、航向连续性和延迟稳定性。它不要求先宣称“完整机身IMU已得到”，也不能把现有固定机身试验当作这些条件已经成立的证据。

## 验证边界

新增控制/视频分层策略与跨状态回归；固定55项均保留。研究包15项覆盖完整姿态可观测条件下的空间变换、五类运动、复合旋转、跨±180°、异频时刻对齐、过期、限位恢复；该包未接入实际发送，不能把数学测试计作挂脖功能通过。云端编译结果另记；真机断连原因、故障修复效果与挂脖算法仍不得写成硬件通过。
