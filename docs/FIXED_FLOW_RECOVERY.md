## 已确认的代码问题及修复

1. `CalibrationSheet` 独立于 RootView，控制器及评估时间被 ObservationIgnored，而面板没读 controlRevision。仅依赖其它偶然变化不能保证按钮/进度刷新。加入原 controlRevision 与 10Hz telemetryRevision，未增加轮询。
2. `MotionProbe.referenceChanged` 锁存到显式 reset；旧文案把历史观察失效当作当前输入仍中断。现在区分当前输入与历史，明确校准时重设显示观察零点，未偷偷重设运动基准。
3. `HeadphoneMotion.failure` 出错后只在 stop/start 清除，后续成功回调也不能恢复。现在成功回调清除当前错误，保留出错和恢复时间、回调次数及实际间隔；失效的运动校准仍需用户重新建立，不自动恢复跟随。
4. 镜头姿态已在 UDP 队列解析并保存，但 App 原先使用排队的 Main 回调，并在消费时重打时间戳。现在读取同一个原生最新姿态槽，保留 UDP 收包时间；Main 延迟回调不能重写姿态或给旧数据续期。记录入站、解析、Main 交付、有效帧间隔与布局长度；命令编码、单位、符号、限位、ACK、视频接收/解码不改。
5. 校准按钮与动作共享同一组当前输入阻塞原因、同一捕获时钟。历史操作单独标注；镜头真实过期走输入失效路径，不能被“模式未就绪”提前变成另一类暂停，更不触发整机断连。

300ms 反复越界的真机来源仍未被证明：可能是真实遥测间隔、收包/解析延迟或主线程消费延迟。不能凭代码或视频仍在变化就选定其中一种。新诊断区分各阶段后才能量化；未放宽 200/300ms、0.7秒稳定窗口、15样本、12秒校准期限，也未改跟随算法。
