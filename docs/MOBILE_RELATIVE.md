# HeadLink 移动相对控制

## 基线与实际能力

从第23版编译提交 `fba28a5b6b1bd37dedc9d81e0fa5cff6ff578223` 独立分支。保留旧IPA及用户配置，固定模式 `TrackingController.swift`、重力映射、1∶1参数、预览渲染器、bundle ID和iOS 17最低版本不变。本工程是HeadLink，未改PulsePods。

| 能力 | 已核实的接口及限制 |
|---|---|
| 耳机 | Apple Core Motion 的 CMHeadphoneMotionManager：姿态四元数、重力、角速度、传感器时间。沿用HeadLink重力方向基准，鼻尖+Y、右+X、上+Z；yaw正为向右，pitch正为抬头。耳机参考不是统一的相机世界航向。 |
| 相机链路 | CoreBluetooth配对、相机Wi-Fi、上游UDP/DUML共享控制与视频。锁定OpenCine版本仍为 `acc38b57d43d4308c79ad5ce951bcb6f44d14d68`。不是官方移动机身SDK。 |
| 相机姿态 | 50字节 `04/05`：handle yaw @4，native pitch @0，显示tilt为负@20，0.1°。上游 `WorldLevel+DJI.swift` 将@24–39解释为世界到镜头四元数；重力方向证据较强，航向自由、横滚符号未完整确认。没有验证独立机身四元数、同步源时间、关节完整三轴及安装外参。不能把镜头姿态或iPhone当机身姿态。 |
| 控制 | 已有 `04/14` 绝对目标模式05，0.1°、roll忽略、100ms指令；模式04零增量100ms用于停止。已有 `04/01` 虚拟摇杆，但未验证其数值对应固定°/秒，本轮不用作角速度标定。目标/停止均为notify，无ACK或到位保证。 |
| 模式及边界 | 读取实际Follow族与2秒云台参数查询的俯仰锁状态。移动必须有新鲜Follow且俯仰未锁；不擅自写模式。请机身关闭ActiveTrack/智能跟随，当前适配器不能可靠核实该状态。保留既有Pocket 4协议范围yaw -48…225°、pitch -44…70°与原不可穿越扇区检查，实际机械范围仍待量测。仅对正式已识别型号启用。 |

参考：[Apple耳机运动接口](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager)、[DJI Pocket 4支持](https://www.dji.com/support/product/osmo-pocket-4)。DJI机内穿戴模式不等于HeadLink可获得独立机身姿态；HeadLink不自动选择该模式。

## 相对语义与恢复

- 固定模式保留校准后的方向对应。移动模式用头部增量拨动相机当前姿态，没在出厂/设备数据里假定存在世界补偿。每段头动开始于最新实际镜头角度；短目标过渡结束后不继续发送纠偏，机身运动由相机自身Follow和稳定机制决定。头部转回会向反向拨动；不像固定模式那样保证回到同一个世界方向。
- 移动“居中”仅建立头部参考，从当前镜头位置起步，不发机械回中指令。已暂停时居中不启动；模式切换停止/清队列，不重复订阅。断连或进入后台后不能自动恢复运动，重新明确开始从当前姿态起步。
- 四元数投影到重力水平面、航向解包，传感器时钟仅用于连续性；两设备的时效均用本机单调接收时间，不相减设备时钟。耳机200ms、镜头300ms。2个0.1°编码步的迟滞死区，复用轻度平滑和120°/s、720°/s²上限，既有最多约25Hz单槽发送；移动命令另外受原始耳机样本的200ms绝对期限约束。若相机在手持时已独立改变姿态，待发目标离实际回报超过一个既有100ms命令的速度预算（12°），即停旧槽并从实测姿态重接，不追旧目标、不重设头部零点。
- 限位舍弃往外的超额增量，反向无需偿还累计角。另一轴在当前合法回报/路径许可时继续。移动的俯仰使用最新native pitch减去显示俯仰误差，沿用上游的小角度映射。极端倾斜、真实回报超界、FPV/俯仰锁或未知路径均暂停，不假定任意握持可用。
- 短缺样或临时模式/传输异常：安全停发/清槽；同一会话和连续头部参考，1秒内恢复时采纳当前头和镜头，不追赶缺失增量。无效四元数先停发；传感器时间回退/参考突变或耳机重连代次变化使参考失效。目标拒绝仅允许一次有界自动重新交接，第二次停至手动开始。
- 第23版能静态确认两条混淆来源：固定反馈偏差被处理为跟随暂停；心跳路径判定只看视频而未尊重新鲜控制回报。现有旧诊断没有本次移动故障证据，不能断言真机根因。新版让新鲜控制回报阻止路径误判；移动模式的视频呈现/重订阅修复不停止仍健康的控制；共享UDP确需重建才停运动。真断连时原设备有一次同身份自动恢复机会；Wi-Fi不具备条件时提示手动加入，恢复通信不启动运动。
- 诊断分别有耳机回调/代次、姿态时效、控制回报/连接代次、视频各阶段、云台模式、目标拒绝类型、移动暂缓/参考/目标。命令提交不是确认；移动不把固定世界误差套到移动镜头，不声称读到机身姿态。没有消除走路平移或视差。

## 真机验收（各项均待验证）

| 操作 | 预期与要记录的证据 |
|---|---|
| 1 固定机身转头 | 保留1∶1、原校准与录像；录屏和实际云台方向。 |
| 2 头不动，平移 | 不产生头部增量命令；画面位移可发生；确认控制回报和视频继续。 |
| 3 头不动，慢转机身 | 不发送反向锁世界指令；由设备Follow决定实际朝向。 |
| 4 同时转头和转机身 | 有平滑拨动，不声称抵消机身角；记录是否回弹/争抢。 |
| 5 正常走动 | 维持合法握持角域；检查图传、录像与真实回报，平移和角度分别观察。 |
| 6 到边界反向 | 边界提示，不重校或断连；反向应很快离开合法边界。 |
| 7 切后台返回 | 重新接收数据，尝试恢复原相机；云台不自启动。 |
| 8 AirPods切换再连 | 路由/参考变化停止；连续恢复与需要居中分别提示。 |
| 9 相机短断再连 | 停止旧队列；仅有界原设备恢复；明确开始，不追赶过去目标。 |
| 10 左右横屏 | 预览按原比例，侧边模式、居中、开始/暂停、录像可点击；核对大字体/左手布局。 |

自动测试不替代以上任何硬件结论。遇到故障，在更多→本地诊断生成脱敏JSON；现有录像与控制各自报告，不必重新口述已描述的现象。
